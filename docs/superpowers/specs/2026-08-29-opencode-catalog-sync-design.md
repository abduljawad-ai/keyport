# OpenCode Catalog Sync + Searchable Model Picker (2026-08-29)

Extends `2026-08-29-provider-catalog-design.md` (first-class providers, shipped).
This design syncs the user's local opencode (v1.18.25) model catalog into Keyport
and replaces the native `<select>` model dropdown with a searchable picker.

## Problem
The user's opencode CLI ships 685 models across 13 provider groups. Keyport shows
short curated lists (4 native providers + 25 named presets with ~5-10 models each).
The user wants Keyport's provider/model lists to match opencode: "same amount of
models, same models and providers". 369-option native `<select>` lists are unusable,
so a searchable picker is required.

## Scope (user-approved)
- **621/685 opencode models are BYOK-usable** (work with a pasted API key in
  Keyport). 64 are excluded: opencode gateway models (big-pickle etc., 7),
  unorouter/tokenrouter routing shims (52), colab-josie (1), plus duplicate
  aliases (mistral-coder1-5, mistral-glm — 5 extra).
- After a **chat-only filter** (models that cannot run in a text chat:
  embeddings, audio/tts/whisper, image/video/music gen, classifiers, realtime,
  OCR), the final count is **540 unique ids across 7 providers** (verified
  from the committed snapshot at `scripts/fixtures/opencode-models.snapshot.txt`):
  openrouter 343, nvidia 91, alibaba 46, google 19, mistral-official 27
  (after dedupe of codestral/glm aliases), groq 7, ovh 7.
- **Mapping correction (self-review):** opencode's `mistral`, `mistral-coder*`,
  `mistral-glm` groups all hit the Mistral API (`api.mistral.ai`) — which is
  Keyport's EXISTING named provider **`mistral-official`**. No new `mistral`
  id. So 7 synced providers = `openrouter`, `nvidia` (new), `alibaba`,
  `google`, `mistral-official`, `groq`, `ovh` (new).
- **New named providers added:** `nvidia` (NVIDIA NIM,
  `https://integrate.api.nvidia.com/v1`) and `ovh` (OVHcloud AI Endpoints,
  `https://oai.endpoints.kepler.ai.cloud.ovh.net/v1`). Both OpenAI-compatible,
  Bearer-key auth, model ids equal to the opencode suffix.
- **Non-chat families dropped** (never usable in chat): embedding/rerank,
  whisper/audio/transcribe/tts (incl. groq allam, Canopy orpheus), omni
  multimodal/realtime (qwen-omni-*, omni-moderation), qwen-mt (machine
  translation), flux/veo/lyria/image-gen, video preview, prompt-guard/safeguard
  classifiers, realtime/live-preview, computer-use, OCR (qwen-vl-ocr).

## Design

### 1. Catalog data + codegen
- New `scripts/sync-opencode-catalog.mjs` (node, zero deps):
  1. Runs `opencode models` (inherits user config), reads stdout lines
     (or reads stdin when piped — enables deterministic fixture testing).
  2. Parses `provider/model-id`; API id = everything after the first `/`.
  3. Maps groups → Keyport provider ids:
     `openrouter, openrouter-free → openrouter`; `nvidia → nvidia`;
     `alibaba → alibaba`; `google → google`;
     `mistral, mistral-coder1-5, mistral-glm → mistral-official`;
     `groq → groq`; `ovh → ovh`. Anything else (opencode, unorouter,
     tokenrouter, colab-josie) is skipped.
  4. Applies the chat-only filter (keyword blocklist above, case-insensitive
     substring on the API id).
  5. Dedupes by `(providerId, apiId)` (codestral-latest ×6 → 1, zai-glm-5-2 ×2 → 1).
  6. Sorts ids within each provider (localeCompare).
  7. Writes `src/shared/data/opencodeCatalog.generated.ts`:
     ```ts
     // GENERATED by scripts/sync-opencode-catalog.mjs — do not edit.
     // Source: `opencode models` (opencode-ai v1.18.25) on 2026-08-29.
     export const OPENCODE_CATALOG: Readonly<Record<string, readonly string[]>> = {
       openrouter: [ ... ],
       ...
     };
     ```
     Flags: `--source cli|stdin` (default cli), `--output <path>`
     (default the generated path) — stdin + temp output enables a
     deterministic fixture test without the opencode CLI.
- The generated file is committed. Re-run the script when opencode's list changes.
- The data file stores PURE model id strings. Families (vendor segment) are
  derived at render time, not baked into the file.

### 2. Providers (frontend + backend)
- `supabase/functions/_shared/providers/registry.ts`: add `nvidia` and `ovh`
  with `apiStyle: 'openai-compatible'` and locked `baseUrl`
  (nvidia: `https://integrate.api.nvidia.com/v1`,
  ovh: `https://oai.endpoints.kepler.ai.cloud.ovh.net/v1`).
  `isCustomProvider` stays false for both. No SSRF surface (locked URLs).
- Frontend `src/shared/types/provider.ts`: add `nvidia`, `ovh` to
  `PROVIDER_IDS`/`PROVIDER_LABELS` (display: "NVIDIA", "OVHcloud").
- `src/shared/types/providerPresets.ts`: add `nvidia` + `ovh` presets with
  `category: 'inference'` (inference platforms — the `cloud` category reads as
  "Cloud Resellers", which doesn't fit NVIDIA NIM / OVHcloud AI Endpoints);
  add both ids to `NAMED_PRESET_IDS`; **remove `models` arrays for the 7
  synced providers** (openrouter, nvidia, alibaba, google, mistral-official,
  groq, ovh) — catalog is authoritative; no duplication. `google` is a
  builtin-native provider, so its catalog entry only feeds
  `getModelsForProvider` (see §4), no preset entry needed for google.
- `PROVIDER_DEFAULT_MODELS` in `provider.ts` currently auto-derives defaults
  from each named preset's `models[0]`; with preset lists removed that would
  become `null`. Fix: add **explicit flagship defaults** for the synced
  providers in the explicit section of the map (e.g. openrouter → a strong `~`
  model, groq → `llama-3.3-70b-versatile`, alibaba → `qwen-max`,
  mistral-official → `mistral-large-latest`, nvidia/ovh → first catalog entry),
  keep the auto-map only for non-synced named presets.

### 3. Searchable `ModelPicker` (new zero-dep component)
Path: `src/shared/ui/ModelPicker/` (index.tsx + module.css).
- **Trigger**: button that shows the current model id (+ provider context for
  clarity in the dialog variant). Click opens popover.
- **Popover**: text input at top (autofocused), below a scrollable list.
  - Filter: case-insensitive substring match on the model id.
  - Grouped by family: for ids with `/`, family = first segment with any
    leading `~` stripped (e.g. openrouter `~anthropic/claude-opus-4` →
    "anthropic", nvidia `deepseek-ai/deepseek-v4-flash` → "deepseek-ai",
    groq `openai/gpt-oss-120b` → "openai"); for ids without `/`, family = "All".
  - Keyboard: ArrowUp/Down move selection, Enter selects, Esc closes,
    outside click closes (focus trap within popover).
  - Empty state: "No models match '…'".
  - Current value not in the catalog (custom/loaded model): pinned selectable
    row "**{id}** (current)" at the top so selection is never lost.
- Accessibility: `role="combobox"`, `aria-expanded`, listbox with options;
  trigger announces current value.
- **Reuses `getModelOptions` from `providerModels.ts`** — its existing
  "unknown current → pinned **(custom)** row" behavior gives the picker its
  current-value pinning for free.

### 4. Wiring
- `src/shared/types/providerModels.ts`: `getModelsForProvider(providerId)` —
  **catalog first** (`OPENCODE_CATALOG[providerId]` → `{ id, label: id,
  family: derived }`), then curated native `PROVIDER_MODELS` (openai/anthropic
  are not in opencode's BYOK set; google's curated array stays as fallback but
  the catalog's 20 ids win), then preset fallback, then `null` (custom →
  free text). `getModelOptions` semantics unchanged (dedupe, unknown-current
  pinning stays in the caller). Family derivation lives in this module
  (see §3) so Composer/dialog get grouped options without changing the data file.
- Composer (`src/features/chat/ui/Composer.tsx`): replace the family-optgroup
  `<select>` branch with `ModelPicker` (options from `getModelOptions` as
  today); `openai-compatible` (Custom) keeps its free-text `Input`.
  Picker disabled while streaming, same as the select today.
- Add-provider dialog: default-model field uses `ModelPicker`.
- `mockEdgeApi` list-models: fall back to the catalog for named providers —
  `MOCK_PROVIDER_MODELS[providerId] ?? OPENCODE_CATALOG[providerId] ??
  presetModels` (catalog before preset; keep `MOCK_PROVIDER_MODELS` first so
  existing mock tests for openai/anthropic lists stay green).

### 5. Tests
- `opencodeCatalog.test.ts` (or shape test in catalog barrel):
  ids non-empty, unique, strictly sorted, keys ⊆ known provider set.
- Codegen determinism: run script on a fixture input twice → identical output
  (fixture-ized; script accepts stdin so the test does not need the opencode CLI).
- `ModelPicker.test.tsx`: filter reduces list; keyboard selection; Enter
  commits; Esc closes; current-not-in-list pinned row selectable; outside click closes.
- Registry consistency test extends to nvidia/ovh (frontend preset base URLs
  equal backend registry URLs).

### 6. Verification & deploy
- `npm run test` full suite green, `tsc --noEmit` clean.
- Regenerate catalog from live `opencode models`.
- Redeploy all edge functions whose bundle includes the registry: chat,
  test-api-key, save-api-key, list-models, register-key (SMTP side unaffected),
  delete-key (registry import) — verify each deploy succeeds.
- Browser verify: Composer picker filters 355 OpenRouter models, dialog works,
  live list-models sync for a real key still replaces catalog on load,
  custom free-text path unchanged.

## Non-goals
- No runtime fetch of model catalogs (no network dependency).
- No syncing of `opencode` gateway / unorouter / tokenrouter / colab providers.
- No visual redesign of the Composer beyond the picker.
- No SSRF/reachability changes for named providers (locked URLs remain).
